# MiniDB Studio 设计规范

## 1. 设计结论

推荐方向：**A「玉白·松绿」**。

它沿用现有 `#F7FAF8 / #FFFFFF / #23866B` 的正确基础，但把产品品质放在信息架构、空间比例、对象上下文、状态反馈和组件一致性上，而不是只换颜色。目标不是把 MiniDB 变成宣传网站，而是形成一个新手看得懂、熟练用户用得快、教学实验讲得清的数据库工作台。

设计原则：

1. 任务先于宣传：开始页首先回答“现在能做什么”。
2. 应用导航与对象导航分离：功能菜单不和数据库表树竞争。
3. 上下文持续可见：数据库、工作库 / 实验库、表 / 实验、连接和事务状态不丢失。
4. 编辑器、表格、树和实验观察器各用最适合自己的布局，不把所有内容都塞进卡片。
5. 危险操作说清对象和影响；状态不只靠颜色。
6. 原型数据必须标注为示例；正式结果仍来自真实 Java 内核。

## 2. 真实产品与技术架构盘点

### 2.1 当前技术栈

| 层 | 当前实现 | 设计约束 |
| --- | --- | --- |
| 前端 | React 18 + TypeScript + Vite | 不推翻，不新增框架 |
| 编辑器 | CodeMirror 6（`@uiw/react-codemirror` + `@codemirror/lang-sql`） | 正式落地继续使用，不退回 `<textarea>` |
| 路由 | `frontend/src/router.ts` 自研 hash 路由 | 保留 11 条现有路由语义 |
| 状态 | `frontend/src/stores/app.tsx` Context + localStorage | 可扩展，不新增状态库 |
| API | `frontend/src/api/client.ts` 统一 JSON envelope + session header/cookie/query fallback | 不改已有协议；新能力单独评审 |
| 服务 | JDK 17 `HttpServer` + Jackson | 仅本机 `127.0.0.1`，真实内核单一来源 |
| 静态发布 | Vite build → `src/main/resources/webroot` → Studio fat JAR | 保留 Windows 双击启动与健康验证 |

正式前端入口为 `frontend/src/main.tsx` → `App.tsx` → `StudioLayout`；页面按 feature 组织：

- `features/database/StartPage.tsx`、`HelpPage.tsx`
- `features/table/DatabasePage.tsx`
- `features/sql/SqlPage.tsx`
- `features/index/IndexPlanPage.tsx`
- `features/labs/` 下六个实验页面

### 2.2 文档与实现差异 / 实际发现

这些不是本轮顺手修复项，但会影响正式设计落地：

1. **“执行选中”当前未真正使用选区。** `SqlPage.tsx` 会检查是否有选区，但随后仍调用 `run()`，而 `run()` 把完整 `sqlText` 交给 `/sql/execute`。正式落地前应写前端回归用例并修正，不在本轮原型中冒充已修复。
2. **“停止”当前只有提示，没有停止执行链路。** `stopRef.current` 被设置，但没有在执行循环或 API 请求中读取；如果要做到可取消，需要明确前端逐语句策略或后端 cancel 能力。
3. **示例库空目录参数与 `--data-dir` 行为不一致。** 实际运行 `createSample('')` 时，`school.db` 出现在服务工作目录，而不是传入的隔离 data dir。截图测试仍在隔离 worktree 内完成，但该差异应单独修复与回归。
4. **NULL 与空字符串尚不是完整产品能力。** 当前编辑表单把空输入转换为 `null`，同时文案明确内核存储层不支持 NULL。新视觉可以显示语义规范，但正式支持需要内核 / API 设计审批，不能只靠前端伪造。
5. **SQL 草稿是全局键。** 当前 `minidb-studio-sql-draft` 没有按数据库或编辑器页签隔离；切库 / 多草稿防丢失需要前端交互调整。
6. 仓库内未找到 `AGENTS.md`，所以本轮以 README、`MiniDB 前端交互界面计划.md`、`MiniDB-Web-Integration-Notes.md`、`docs/studio/` 和实际源码为准。

## 3. 当前界面问题（六个证据维度）

| 维度 | 真实页面 / 操作 | 影响 | 新方案 |
| --- | --- | --- | --- |
| 信息层级 | `StudioLayout` 顶栏把数据库、连接、事务、表数同权平铺 | 状态都可见，但当前任务 / 当前对象不突出 | 数据库切换器作为主上下文；连接 / 事务为状态 chip；对象头显示表或实验 |
| 功能发现 | 主导航 11 个入口混用 Emoji；实验入口与普通功能同样呈现 | 语义和线宽不一致；新用户难看出“实验室是一组” | 本地 SVG 统一 1.7px 线宽；工作区 / 分析 / 实验 / 帮助四组；实验可展开但入口不隐藏 |
| 操作路径 | 开始页快捷卡、两个路径输入框、新手引导重复讲创建 / 打开 | 首屏任务较多，但“下一步”与当前数据库状态分开 | 三个任务入口 + 最近数据库 + 基于上下文的下一步；路径输入进入弹窗 |
| 阅读密度 | SQL 编辑器固定 200px，结果区和巨大留白比例失衡 | 编辑与结果不是首屏视觉主角 | 约 245px 编辑器 + 独立结果面板；状态在同一容器切换 |
| 状态反馈 | Toast 3.5 秒消失；执行中、错误、空结果分散 | 长过程、会话和安全反馈难回看 | 局部持久状态 + 全局事务状态 + Toast 只做完成提示；错误紧邻结果区 |
| 一致性 | 页面大量 inline style 与通用 `card` | 工具栏、页头、详情和实验难形成稳定体系 | tokens + Surface / ObjectHeader / Toolbar / DataGrid / Notice / LabFrame 等复用结构 |

数据库管理页增加**对象导航**，只负责数据库内的表；它不是第二套应用菜单。中央区域显示当前表的数据 / 结构 / 索引，表切换时保持当前页签策略可在实现评审时决定。

## 7. 组件规范

### 7.1 全局外壳

- `TopBar`：数据库切换器、连接状态、事务状态必须持续可见。
- `AppNav`：中文文字 + 统一 SVG；实验组可折叠，但六项不可藏入多层菜单。
- `ObjectRail`：只在数据库对象任务出现；搜索、表名、行数、索引数。
- 1024px：主导航缩至 160px，对象导航缩至 190px；中央工作区滚动，整页不横向溢出。

### 7.2 数据表格

- 表格容器负责横向滚动；操作列 sticky。
- 列头显示名称和类型；RID 使用等宽字体。
- `NULL`、空字符串、长内容、BIGINT 有不同视觉语义。
- 选中行同时使用背景和复选框状态。
- 页脚显示范围 / 总行数 / 来源明确的耗时。

### 7.3 SQL 工作台

- CodeMirror 编辑区和结果区占据首屏主体。
- 工具栏顺序：执行 SQL、执行选中、执行计划、停止；事务控件固定在右侧。
- 五种状态在同一结果容器显示：未执行 / 执行中 / 成功 / 错误 / 空结果。
- 错误展示 code、行列、原 SQL 片段、修复入口；不清空编辑器。
- 事务 ACTIVE 同时显示在顶栏和工具栏。

### 7.4 危险确认

弹窗必须显示：

1. 当前数据库与工作库 / 实验库属性；
2. 表、索引、RID 或实验文件；
3. 影响行数 / 数据页 / 是否可回滚；
4. 明确动词按钮，如“删除这条记录”“重置实验库”。

### 7.5 实验框架

共同节奏：理解目标 → 设置条件 → 执行操作 → 观察结果 → 解释现象。

| 实验 | 专属观察方式 |
| --- | --- |
| 存储与缓冲池 | 页地图、页内条带、slot 表、buffer pool 状态 |
| SQL 流水线 | Token / AST / Plan / Result 阶段链 |
| 事务与锁 | 双会话控制台、锁等待图、持久日志 |
| WAL 与恢复 | crash / redo / undo 时间线、WAL 与一致性证据 |
| 性能 | 控制变量表单、计划对比、实时测量来源 |
| JDBC | 代码、调用步骤、事务日志、最终数据 |

## 8. 关键流程对比

| 任务 | 当前路径 | 新方案路径 | 变化 |
| --- | --- | --- | --- |
| 打开最近数据库 | 开始 → 最近列表 → 数据页 | 开始 → 最近数据库行 | 点击数不变；对象 / 状态更清楚 |
| 浏览 student | 数据浏览 → 左侧表 → 数据 | 数据库管理 → 对象导航 student | 应用 / 对象层级分离 |
| 执行查询 | SQL → 编辑 → 执行 → 结果 | SQL → 编辑 → 执行 SQL → 结果 | 保留快捷键；状态更完整 |
| 查看计划 | SQL / 索引页分别查看 | SQL 结果页签或索引观察器 | 两入口保留；对象上下文一致 |
| 提交事务 | SQL 工具栏 | SQL 工具栏 + 顶栏状态 | 操作不增加，风险可见 |
| 重置实验 | 实验页按钮 | 实验安全条 → 明确确认 | 保留安全确认，不为减点击而删除 |

## 9. 实施计划（待批准）

### 阶段 0：冻结设计边界

- 审核本目录的方向、信息架构、工作台比例和安全文案。
- 不进入正式页面修改，直到用户明确批准。

### 阶段 1：纯视觉调整（低风险）

对应文件：

- `frontend/src/styles.css`
- `frontend/src/components/ui.tsx`

工作：集中 tokens、统一本地 SVG、顶栏 / 主导航 / Button / Tabs / Table / Notice / Modal 样式。不得修改 API、数据库内核或依赖清单。

### 阶段 2：高频前端交互（中风险）

对应文件：
