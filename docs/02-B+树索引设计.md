# MiniDB 设计文档 02：B+ 树索引

> 对应阶段 2 + 变长键增强轮。代码：`minidb.btree.BPlusTree / BTreeNode`，索引元数据接入 `minidb.storage.Database / Catalog`（`IndexKeys` 门面统一键编码）。40+ 项测试（含 String 版 TreeMap 对拍）。

## 1. 定位与接口

- **变长键（UTF-8 字节序），value = Rid(pageId, slot)**：INT/BIGINT 列经 `encodeLong`（符号位翻转 → 8 字节，数值序=字节序）复用 long 门面；VARCHAR(n≤255) 列直接走 String 门面。唯一索引，NULL 值不入索引。
- 对外 API：`insert/delete/search`（long 与 String 双重载）、`rangeScan`（**开闭边界可选**，String 版 null=无界）、`scanAll`、`stats()`、`validate()`。
- **铁律的落地**：节点即 4KB 页，全部读写经 BufferPool——索引页与数据页共享同一套脏页/淘汰/恢复语义（steal 协议下索引页同样经 FlushHook 保证 WAL 先写）。

## 2. 节点布局（变长键双端布局）

| 区域 | 布局 |
|------|------|
| 头 16B | type / numKeys / next / prev / 布局标志(=1) / **键数据区物理末端 OFF_END** |
| 目录 | `int[i] @ 16+4i`——键 i 条目的起始偏移，自前向后增长 |
| 键区 | `[len short][UTF-8 bytes]` 紧凑排布，物理序=逻辑序，**始终紧贴目录压实** |
| 值/子指针区 | 叶 Rid（8B）/ 内部子指针（4B）自页尾向前增长 |

键长上限 **KEY_MAX=255 字节**：保证页满 ≥15 键、字节均衡分裂每侧 ≥7 键、合并 ≤14 键必放回一页——经典 B+ 树不变量（minKeys=7、借位/合并）全保留，无大键特例。插入"按需预分裂"（放不下才分裂，字节均衡）；删除借位前提是父分隔键可原位替换（`fitsReplace`），字节放不下时容忍暂时 underflow 自愈。10 万随机 8 字节键实测树高 3、约 540 叶。

## 3. 插入：分裂

1. 沿树下行到叶，键已存在且 rid 相同则幂等返回（`createIndex` 要求唯一，重复键在建索引时即拒绝）。
2. 叶满 → **push-right 分裂**：新右节点取走后半，分隔键**保留在右节点**（B+ 树内部分隔键是"右子树最小键"的副本），父节点插入指向右节点的指针。
3. 内部节点满 → **中间键上推**（分裂后中间键只留在父节点，B 与 B+ 的关键区别在此）。
4. 根分裂 → 新根（两孩子），树高 +1。

## 4. 删除：借位与合并

低于最小键数时，按序尝试：

1. **向左兄弟借位（旋转）**：左兄弟末键移到本节点头，父分隔键同步更新为新的边界键。
2. **向右兄弟借位**：对称。
3. **借不到（兄弟都半满）→ 合并**：本节点并入兄弟，父分隔键**下坠删除**，父节点可能继续下溢 → 递归处理。
4. 根只剩一个孩子 → **根降级**，树高 -1；根为空叶（0 键）也合法（空索引）。

叶链 prev/next 在分裂/合并时同步维护，这是范围扫描正确性的生命线，`validate()` 专门校验双向一致。

## 5. 范围扫描

`rangeScan(from, fromInc, to, toInc)`：下行定位 from 叶 → 沿叶链 next 向右，直到越过 to。四个布尔参数让 `>=, >, <, <=, =` 统一成一个入口。**同列多个比较谓词先在执行器合并成一段区间**再进树（见文档 04——这个合并优化让范围查询从 73 ms/次降到 0.222 ms/次）。

## 6. 与存储层的集成

- `Database.createIndex(name, table, column)`：全表扫描现有数据 → 逐行 `(key, rid)` 插入树 → 根页号登记进 Catalog。
- `dropIndex / dropTable`：**遍历整棵树释放全部节点页**还给 StorageEngine，不是简单忘掉根页号——否则页泄漏。
- DML 同步：INSERT/DELETE/UPDATE 由 Executor 维护索引（UPDATE 若索引列值未变则**跳过删插**，避免并发窗口漏行，见文档 05）。

## 7. 正确性验证（对拍 TreeMap）

`BPlusTreeTest` + `DatabaseIndexTest` 共 36 项，核心是**与 `java.util.TreeMap` 对拍**：

- 随机插入 **10 万 key**：等值查找、全序扫描、20 组随机范围扫描 vs `subMap` 逐条完全一致；
- 随机删除 **5 万 key** 后再对拍一轮；
- 关闭重开文件，树结构/数据一致（持久化验证）；
- **8 页小缓冲池**下 3000 键压力测试（强制频繁淘汰/写回，验证没绕过缓冲池）；
- `validate()` 在每轮操作后跑：键有序、子树边界一致、叶链双向一致、键数守恒；
- 故障注入：坏页类型字节、根页丢失等异常路径。

## 8. 性能（PERF.md）

| 操作 | 结果 |
|------|------|
| 10 万随机键建树 | 477 ms（定长键时代）/ 1.52 s（SQL 逐行，变长键布局） |
| SQL 点查 vs 全表扫描 | **≈ 818×**（0.055 ms vs 45 ms） |
| VARCHAR 索引 | 等值 + 范围 + 前缀（开闭界 rangeScan），对拍 TreeMap 一致 |

## 9. 取舍与已知限制

| 决策 | 理由 | 代价 |
|------|------|------|
| 变长键上限 255B | 保住经典 B+ 树不变量，免大键特例 | 超长 VARCHAR 不可索引（建索引即拒绝） |
| 单列索引 | 教学聚焦 | 复合索引未支持 |
| 唯一索引限制 | 免去"同 key 多 Rid"的重复键管理 | 非唯一列建索引被拒绝 |
| 无前缀压缩 | 4KB 页 fanout 已足够（338） | 叶利用率略低 |
| 乐观并发未做 | 并发控制统一在锁层（文档 05） | 树操作串行于行锁之后 |
