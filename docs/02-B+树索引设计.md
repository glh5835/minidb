# MiniDB 设计文档 02：B+ 树索引

> 对应阶段 2。代码：`minidb.btree.BPlusTree / BTreeNode`（约 900 行），索引元数据接入 `minidb.storage.Database / Catalog`。36 项测试。

## 1. 定位与接口

- **key = long，value = Rid(pageId, slot)**：只支持 INT/BIGINT 列建索引（`Database.createIndex` 校验并要求唯一）。行存主路径不受索引影响，索引是"RID → 行"的加速结构。
- 对外 API：`insert(key, rid)`、`delete(key, rid)`、`get(key)`（等值）、`rangeScan(from, fromInc, to, toInc)`（**开闭边界可选**）、`scan()`（叶链全序）、`stats()`（树高/节点数/利用率/键数）、`validate()`（结构不变量自检）。
- **铁律的落地**：节点即 4KB 页，全部读写经 BufferPool（`pool.getPage` / `page.setDirty`），代码中没有任何直接 `DiskManager` 调用——这保证了索引页与数据页共享同一套脏页/淘汰/恢复语义。

## 2. 节点布局（BTreeNode）

| 节点 | 4KB 内布局 | 容量 |
|------|-----------|------|
| 叶节点 | 头 + 键 long 数组 + Rid 数组 + prev/next 叶指针 | **255 键** |
| 内部节点 | 头 + 键数组 + 子页号数组 | **fanout 338** |

分裂/合并的最小键数约束按常规 m 阶 B+ 树：非根节点至少半满。10 万随机键建树实测树高 3、叶 7812 页、利用率 50.2%（PERF.md）。

## 3. 插入：分裂

1. 沿树下行到叶，键已存在且 rid 相同则幂等返回（`createIndex` 要求唯一，重复键在建索引时即拒绝）。
2. 叶满 → **push-right 分裂**：新右节点取走后半，分隔键**保留在右节点**（B+ 树内部分隔键是"右子树最小键"的副本），父节点插入指向右节点的指针。
3. 内部节点满 → **中间键上推**（分裂后中间键只留在父节点，B 与 B+ 的关键区别在此）。
4. 根分裂 → 新根（两孩子），树高 +1。

## 4. 删除：借位与合并

低于最小键数时，按序尝试：

1. **向左兄弟借位（旋转）**：左兄弟末键移到本节点头，父分隔键同步更新为新的边界键。
2. **向右兄弟借位**：对称。
3. **借不到（兄弟都半满）→ 合并**：本节点并入兄弟，父分隔键**下坠删除**，父节点可能继续下溢 → 递归处理。
4. 根只剩一个孩子 → **根降级**，树高 -1；根为空叶（0 键）也合法（空索引）。

叶链 prev/next 在分裂/合并时同步维护，这是范围扫描正确性的生命线，`validate()` 专门校验双向一致。

## 5. 范围扫描

`rangeScan(from, fromInc, to, toInc)`：下行定位 from 叶 → 沿叶链 next 向右，直到越过 to。四个布尔参数让 `>=, >, <, <=, =` 统一成一个入口。**同列多个比较谓词先在执行器合并成一段区间**再进树（见文档 04——这个合并优化让范围查询从 73 ms/次降到 0.222 ms/次）。

## 6. 与存储层的集成

- `Database.createIndex(name, table, column)`：全表扫描现有数据 → 逐行 `(key, rid)` 插入树 → 根页号登记进 Catalog。
- `dropIndex / dropTable`：**遍历整棵树释放全部节点页**还给 StorageEngine，不是简单忘掉根页号——否则页泄漏。
- DML 同步：INSERT/DELETE/UPDATE 由 Executor 维护索引（UPDATE 若索引列值未变则**跳过删插**，避免并发窗口漏行，见文档 05）。

## 7. 正确性验证（对拍 TreeMap）

`BPlusTreeTest` + `DatabaseIndexTest` 共 36 项，核心是**与 `java.util.TreeMap` 对拍**：

- 随机插入 **10 万 key**：等值查找、全序扫描、20 组随机范围扫描 vs `subMap` 逐条完全一致；
- 随机删除 **5 万 key** 后再对拍一轮；
- 关闭重开文件，树结构/数据一致（持久化验证）；
- **8 页小缓冲池**下 3000 键压力测试（强制频繁淘汰/写回，验证没绕过缓冲池）；
- `validate()` 在每轮操作后跑：键有序、子树边界一致、叶链双向一致、键数守恒；
- 故障注入：坏页类型字节、根页丢失等异常路径。

## 8. 性能（PERF.md）

| 操作 | 结果 |
|------|------|
| 10 万随机键建树 | 477 ms，树高 3 |
| JMH 等值查找 | **0.280 µs/op**（±0.136） |
| JMH 插入+删除 | 0.396 µs/op |
| SQL 点查 vs 全表扫描 | **≈ 818×**（0.055 ms vs 45 ms） |

## 9. 取舍与已知限制

| 决策 | 理由 | 代价 |
|------|------|------|
| 只索引整型单列 | key=long 使节点布局最简、可比 TreeMap | VARCHAR/复合索引未支持 |
| 唯一索引限制 | 免去"同 key 多 Rid"的重复键管理 | 非唯一列建索引被拒绝 |
| 无前缀压缩 | 4KB 页 fanout 已足够（338） | 叶利用率略低 |
| 乐观并发未做 | 并发控制统一在锁层（文档 05） | 树操作串行于行锁之后 |
